# HPC Docker Stack

Containerised HPC environment running on Rocky Linux 8.

| Service | Container | Image |
|---|---|---|
| Slurm controller + accounting | `slurmctld` | `slurm-ctld:latest` (built locally) |
| MariaDB (Slurm accounting DB) | `mariadb` | `mariadb:10.11` |
| Open OnDemand web portal | `ondemand` | `ondemand:latest` (built locally) |

Authentication: **FreeIPA** via SSSD for all services.

---

## Architecture

```
                 ┌─────────────────────────────────────┐
                 │           Docker network (hpc)       │
                 │                                      │
  VPN users ─────┤─HTTPS 443──► ondemand (PAM→IPA)     │
                 │                   │                  │
  Nginx proxy ───┤─HTTP  8080──► ondemand (OIDC→SSO)   │
                 │                   │                  │
                 │              munge key               │
                 │                   │                  │
                 │          slurmctld:6817              │
                 │          slurmdbd:6819               │
                 │               │                      │
                 │           mariadb:3306               │
                 └─────────────────────────────────────┘
```

## Prerequisites

- Docker 20.10+ and Docker Compose v2
- Access to FreeIPA server (`ipa.example.com`)
- FreeIPA CA certificate (`ipa/ca.crt`)
- An OIDC provider (Azure AD, Keycloak, etc.) — for port 8080 path only

## First-time setup

### 1 — FreeIPA CA certificate

```bash
# Fetch from your IPA server (adjust hostname)
curl -sk https://ipa.example.com/ipa/config/ca.crt -o ipa/ca.crt

# Or copy from an enrolled client
scp root@ipa.example.com:/etc/ipa/ca.crt ipa/ca.crt
```

### 2 — IPA sync credentials

```bash
cp ipa/ipa.conf.sample ipa/ipa.conf
vi ipa/ipa.conf          # fill in IPA_SERVER, IPA_BIND_DN, IPA_BIND_PASSWORD, etc.
```

### 3 — MariaDB passwords (auto-generated on first build)

`build.sh` generates random passwords automatically if `.env` still contains
`CHANGE_` placeholders. You can also set them manually:

```bash
vi .env
# MARIADB_ROOT_PASSWORD=...
# MARIADB_SLURM_PASSWORD=...
```

### 4 — Slurm config

```bash
vi slurm/conf/slurm.conf        # add your compute NodeName lines
vi slurm/conf/sssd.conf         # set ipa_domain and ipa_server
```
`slurmdbd.conf` is updated automatically by `build.sh` with the generated DB password.

### 5 — OOD config

**VPN/direct users (port 443, PAM auth):**
```bash
vi ondemand/conf/ood_portal_local.yml   # set servername
vi ondemand/conf/sssd.conf              # set ipa_domain and ipa_server (same as slurm)
```

**SSO users via reverse proxy (port 8080, OIDC auth):**
```bash
cp ondemand/conf/ood_portal.yml.sample ondemand/conf/ood_portal.yml
vi ondemand/conf/ood_portal.yml
# Set: servername, trusted_proxies, oidc_provider_metadata_url,
#      oid_client_id, oidc_client_secret
```

## Build

```bash
cd docker

# Build Slurm image (generates munge key to ./munge/munge.key)
./build.sh

# Build Open OnDemand image
docker build -t ondemand:latest ondemand/

# Optional: push to registry with arch tag
./build.sh -t registry.example.com/slurm-ctld:latest -P
```

`build.sh` options:

| Flag | Default | Description |
|---|---|---|
| `-t TAG` | `slurm-ctld:latest` | Image tag |
| `-s VERSION` | `24.05.5` | Slurm version to compile |
| `-k DIR` | `./munge` | Host directory for munge key |
| `-P` | — | Push arch-specific tag to registry |
| `-M` | — | Create and push multi-arch manifest |
| `-n` | — | Skip munge key export |

## Authentication paths

### Path A — VPN / direct access (port 443)

Users on VPN browse to `https://ondemand.example.com` (port 443).
Apache challenges with HTTP Basic auth. Credentials are verified via
PAM → SSSD → FreeIPA.

```
Browser (VPN) ──HTTPS 443──► Apache (mod_authnz_pam)
                                   └──► SSSD ──► FreeIPA
```

No OIDC provider needed. SSL cert is the self-signed cert generated at
startup, or mount a real cert (see [SSL certificates](#ssl-certificates)).

### Path B — External reverse proxy (port 8080)

An nginx/HAProxy instance (separate VM or container) terminates SSL and
forwards to OOD on port 8080. OOD authenticates the session via OIDC.

```
Browser ──HTTPS 443──► nginx (SSL termination)
                            └──HTTP 8080──► Apache (mod_auth_openidc)
                                                └──► OIDC provider (SSO)
```

**nginx configuration example:**
```nginx
server {
    listen 443 ssl;
    server_name ondemand.example.com;

    ssl_certificate     /etc/ssl/certs/ondemand.crt;
    ssl_certificate_key /etc/ssl/private/ondemand.key;

    location / {
        proxy_pass         http://ondemand-host:8080;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto https;
        proxy_read_timeout 120s;
    }
}

server {
    listen 80;
    server_name ondemand.example.com;
    return 301 https://$host$request_uri;
}
```

Set `trusted_proxies` in `ood_portal.yml` to the nginx server's IP so OOD
trusts the forwarded headers.

## SSL certificates

By default the container generates a self-signed certificate at startup.
To use a real cert, mount it:

```yaml
# docker-compose.yml — add to ondemand volumes:
- ./certs/ondemand.crt:/etc/pki/tls/certs/ondemand.crt:ro
- ./certs/ondemand.key:/etc/pki/tls/private/ondemand.key:ro
```

The cert files must be present before the container starts (entrypoint
skips generation if they exist).

## Interactive apps and widgets

OOD system apps live at `/var/www/ood/apps/sys/` and public assets at
`/var/www/ood/public/`. Both are bind-mounted from the host:

```
docker/ondemand/apps/    →  /var/www/ood/apps/sys/   (interactive apps)
docker/ondemand/public/  →  /var/www/ood/public/      (widgets, branding)
```

**Changes take effect immediately — no container restart needed.**

To add a custom app:
```bash
# Clone an OOD app into the apps directory
git clone https://github.com/OSC/bc_example_jupyter \
    docker/ondemand/apps/bc_example_jupyter

# It appears in the OOD dashboard on next page load
```

## Slurm operations

```bash
# Check controller status
docker exec slurmctld scontrol ping

# Node and partition summary
docker exec slurmctld sinfo

# Active jobs
docker exec slurmctld squeue

# Accounting — clusters, users, accounts
docker exec slurmctld sacctmgr list cluster
docker exec slurmctld sacctmgr list user

# Submit a test job (requires a compute node joined)
docker exec slurmctld sbatch --wrap="hostname" --partition=compute

# IPA sync log
docker exec slurmctld tail -f /var/log/slurm/sync-ipa.log
```

## Common operations

### Apply config changes without rebuild

Most config files are bind-mounted — edit on host and restart the affected
service inside the container:

```bash
# Slurm config changed
docker exec slurmctld supervisorctl restart slurmctld

# OOD portal config changed (regenerates Apache config)
docker compose up -d --force-recreate ondemand

# IPA sync credentials changed (env_file — must recreate container)
docker compose up -d --force-recreate slurmctld

# SSSD config changed
docker exec ondemand supervisorctl restart sssd
docker exec slurmctld supervisorctl restart sssd
```

### View logs

```bash
docker exec slurmctld  tail -f /var/log/slurm/slurmctld.log
docker exec slurmctld  tail -f /var/log/slurm/slurmdbd.log
docker exec slurmctld  tail -f /var/log/slurm/sync-ipa.log
docker exec ondemand   tail -f /var/log/ondemand/hpc-mac.csn.corp_error.log
docker exec ondemand   tail -f /var/log/ondemand/httpd.log
```

### Regenerate munge key

```bash
# Stop stack, delete old key, rebuild
docker compose down
rm munge/munge.key
./build.sh -n          # rebuild without exporting key
docker run --rm --entrypoint bash slurm-ctld:latest \
  -c 'dd if=/dev/urandom bs=1 count=1024 > /etc/munge/munge.key 2>/dev/null && cat /etc/munge/munge.key' \
  > munge/munge.key
chown 990:990 munge/munge.key && chmod 400 munge/munge.key
docker compose up -d
```

## Troubleshooting

| Symptom | Check |
|---|---|
| `slurmctld` won't start | `docker exec slurmctld cat /var/log/slurm/slurmctld.log` |
| `slurmdbd` won't start | Verify `slurmdbd.conf` StoragePass matches `.env` MARIADB_SLURM_PASSWORD |
| Munge auth errors | Confirm `munge/munge.key` is owned by UID 990 (`ls -ln munge/munge.key`) |
| SSSD fails | Check `sssd.conf` permissions are 600, IPA server reachable |
| OOD 401 on port 443 | Expected — enter IPA username/password |
| OOD 500 on port 8080 | OIDC provider unreachable — check `oidc_provider_metadata_url` in `ood_portal.yml` |
| Port 8080 returns 403 | Set correct `trusted_proxies` in `ood_portal.yml` to match proxy IP |
| IPA users not in Slurm | Check `docker exec slurmctld cat /var/log/slurm/sync-ipa.log` |
